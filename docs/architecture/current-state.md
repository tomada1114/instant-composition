# Current state

An assessment of the code at commit `d2a5cd9`, the starting point for the rewrite. The
application works: a single learner runs Japanese-to-English drills against a local
Next.js server, with progress in a SQLite file. It was built to work first, and it does;
what follows is what carries forward and what stands between it and the target in
[vision.md](vision.md).

## What carries forward

These are seams and assets the rewrite keeps, in substance if not in location.

- **Web-standard handlers.** Every request handler is a factory returning
  `(request: Request) => Promise<Response>` that imports nothing from the framework
  (`src/server/handlers/answers.ts:5-7`), and each route file is a one-line re-export
  (`src/app/api/answers/route.ts:1`). This is why moving the API onto Hono and Lambda is
  re-hosting rather than rewriting
  ([ADR-0007](adr/0007-http-api-contract-and-offline-sync.md)).
- **One environment reader.** `src/server/env.ts` is the only module that reads
  `process.env`, validating it against one schema (`src/server/env.ts:128-133`). The
  target keeps the rule per deployable and routes secrets through the same door.
- **Billing is decided by wiring, not by environment.** `requiresAccessKey` makes an
  endpoint that bills a provider refuse to start unprotected
  (`src/server/env.ts:75-91`). The idea generalizes to "a billed endpoint requires an
  authenticated learner and an entitlement check"
  ([ADR-0010](adr/0010-entitlements-and-billing.md)).
- **Expected failures are values.** `Result` (`src/core/result.ts:15-16`) and the error
  envelope `{ error: { code, message } }` whose `code` is the contract
  (`src/server/http.ts:27-34`) become the API's error model unchanged.
- **A bounded body reader.** Request bodies are read chunk by chunk and abandoned past
  64 KiB rather than trusting `Content-Length` (`src/server/http.ts:16`,
  `src/server/http.ts:51-73`).
- **A pure rule core.** `src/core/` holds the dealing, placement, streak, level and
  scheduling rules as framework-free functions — the seed of `packages/domain`
  ([ADR-0002](adr/0002-architecture-style-and-repository-layout.md)).
- **Time and ids are injected.** The service layer receives `now` and `newId`
  (`src/server/services/deps.ts:4-9`, `src/server/composition.ts:34-35`).
- **Idempotency footholds.** Answer ids are generated by the client and a resend is
  ignored (`src/core/types.ts:41`, `src/server/db/answers.ts:49`); finishing a finished
  round returns its saved summary (`src/server/services/finish.ts:133-135`); starting a
  round resumes today's open one of the same kind
  (`src/server/services/start.ts:150-153`). The offline answer queue builds on exactly
  this.
- **Reviewed content with a quality gate.** A card is shown only when its review stamp
  matches a hash of its core fields (`scripts/cards/schema.mjs:17-26`), so an edited,
  unreviewed card cannot reach a learner. The catalog holds 1,020 cards, all stamped and
  all tagged with grammar items, carrying 2,052 alternative answers; `tombstones.jsonl`
  records 324 deleted cards, each with the reason it was rejected. The alternatives are
  ready-made positive examples for a grading evaluation set, and the rejection reasons
  are labeled negatives for evaluating an automated card reviewer
  ([ADR-0011](adr/0011-llm-integration-and-evaluation.md)).
- **Card tooling and gates.** The `pnpm cards:*` commands (ids, lint, near-duplicate
  checks, tombstones, stamps), the `lefthook` pre-commit layer, the zone boundaries
  enforced twice (ESLint and `tests/boundaries.test.ts`), and 20 authored skills. The
  rewrite changes what these describe, not the discipline they encode.

## What blocks the target

### The progress store has the wrong shape

`ProgressStore` is already an interface (`src/server/db/types.ts:44`), so the problem is
not a missing seam. It is the seam's shape, which cannot sit in front of DynamoDB:

- **Synchronous.** Every method returns a value directly because `node:sqlite` is
  synchronous; all services are synchronous with it.
- **Single-tenant.** No table has a learner column, and `settings` admits exactly one
  row (`CHECK (id = 1)`, `src/server/db/migrations.ts:10`).
- **Caller-wrapped transactions.** Services wrap their own reads and writes in
  `transaction(body)` — ingesting answers (`src/server/services/answer.ts:72-76`) and
  closing a round (`src/server/services/finish.ts:140`). An interactive
  read-modify-write transaction has no DynamoDB equivalent; the replacement is a
  per-command atomic commit with conditions
  ([ADR-0006](adr/0006-persistence-on-dynamodb.md)).
- **Full-log recomputation on every request.** Each call reads every answer ever given
  (`src/server/services/progress.ts:52`) and replays the whole log to rebuild each
  card's Leitner state (`src/core/card-state.ts:23`); finishing a round also reads every
  finished round to total the points (`src/server/services/finish.ts:84-86`). Cost grows
  with a learner's history. The vocabulary prototype hit the same wall and moved its
  review path to point lookups (its issue #45).

### Two entry paths

Pages call the service layer directly — `getServices().home()` from a server component
(`src/app/[locale]/(home)/page.tsx:26`) — while mutations go through the route handlers.
Identity checked only in the proxy or only in handlers would leave the other path open.
The target removes the second path altogether: every client, including the web, goes
through the API ([ADR-0001](adr/0001-server-owned-logic-behind-one-api.md)).

### The practice day depends on the server's time zone

`dayOf` derives the practice day from the process's local clock
(`src/core/day.ts:25-32`), with the 4 a.m. boundary from `src/core/tuning.ts:10`. On a
single-user laptop the server's zone is the learner's; on shared infrastructure it is
not, and every streak, portion and "yesterday" round shifts. AWS Lambda's default time
zone is UTC (`TZ` is a reserved runtime variable; see [references](references.md)),
which moves a Japanese learner's day by nine hours. The time zone becomes a learner
attribute passed into the domain. The vocabulary prototype has the same default
(`vocab: src/core/scheduler.ts:183-195`).

### Offline answers would be stamped on arrival

The server records `answeredAt` as the time the answer reaches it
(`src/server/services/answer.ts:66`). For an answer queued on a phone for hours, that is
wrong for scheduling and for "answered today". The offline contract needs a
client-reported time with server-side bounds
([ADR-0007](adr/0007-http-api-contract-and-offline-sync.md)).

### Language and level are hard-coded

A card's prompt is a field named `ja` (`src/core/types.ts:23-24`), topic names are `ja`
fields (`src/core/types.ts:85-86`), the app reads only the TOEIC reference of each level
although `content/levels.json` also records a CEFR band per level
(`src/server/content/parse.ts:31`), and the grammar list is an English grammar
inventory. Every one of these assumes one language pair
([ADR-0004](adr/0004-multi-language-content-model.md)).

### Content is re-scanned on every read

`ContentSource.get()` stats every content file to compute a signature before deciding
whether to reload (`src/server/content/index.ts:21`). That is the right trade-off for
editing cards against a running dev server, and the wrong one for a function whose
content never changes between deploys; production reads a snapshot built at deploy time.

### Hosting does not fit the managed option

The app is on Next.js `^16.3.4` (`package.json:83`), while Amplify Hosting documents
support for Next.js 12 through 15 ([references](references.md)). Hosting it on AWS would
mean running the Next.js server on Lambda ourselves. With native apps certain, the web
no longer needs a server of its own at all
([ADR-0008](adr/0008-web-client-as-static-spa.md)).

### The rate-limiting rule does not yet distinguish entitlements

AGENTS.md's "Rate limiting" section says the application owns no limiter state and that
caller throughput is enforced at an edge or gateway. A public product with per-learner
LLM allowances or credits needs an entitlement ledger inside the application. That is a
business balance, not throughput limiting, but the section does not yet say so; amending
it is an owner decision ([ADR-0010](adr/0010-entitlements-and-billing.md)).

## The vocabulary prototype (a separate repository)

Built from the same template and just as provisional, it will be rebuilt rather than
merged ([ADR-0003](adr/0003-bounded-contexts-and-activity-integration.md)). What it
contributes is design, not code:

- **FSRS behind one pure function.** `ts-fsrs` is imported only by its scheduler module,
  which exposes `rate(state, rating, nowMs)` with time as an argument and keeps library
  types from leaking (`vocab: src/core/scheduler.ts:56-60` holds the parameters: desired
  retention 0.9, fuzz and short-term steps on).
- **A review log with before and after state.** Each review records the scheduling state
  on both sides, which is what an FSRS parameter optimizer and any later re-scheduling
  need.
- **CEFR levels (A1–C2)** on every card, and a learning scope (purpose, topics, an
  optional exam target).
- **The same single-learner assumptions**: no learner column, one card state per card,
  global key-value settings, a synchronous store, and a server bound to `127.0.0.1`
  without authentication.
- **Different content conventions**: one JSON file per card with an id derived from the
  headword and part of speech, a `retired` flag instead of tombstones, and no review
  stamps.

## The starting hypotheses, judged

Five hypotheses came into the review as candidates, not decisions.

| Hypothesis                                                                                               | Verdict                     | What changed                                                                                                                                                                                                  |
| -------------------------------------------------------------------------------------------------------- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Thread the learner (user id, principal) through every service and store call.                            | Adopted in a different form | Build a `RequestContext` once at the edge and hand services stores already bound to one LearnerId, so no service can name another learner's key ([ADR-0005](adr/0005-identity-and-authorization.md)).         |
| Put stores and content sources behind interfaces so SQLite and files can be swapped for DynamoDB and S3. | Premise did not hold        | The interfaces exist; their shape is the problem (above). Reviewed cards ship as a deploy-time snapshot, not from S3, so code and content release together ([ADR-0006](adr/0006-persistence-on-dynamodb.md)). |
| Define one LLM boundary with schema-typed input and output that reports model, tokens and latency.       | Adopted, later phase        | One port per task (grade, explain, generate), each with its own schema, prompt version and evaluation set, over a single Bedrock client ([ADR-0011](adr/0011-llm-integration-and-evaluation.md)).             |
| Treat grading and generation as jobs with idempotency keys.                                              | Adopted                     | Keys derive from ids that already exist (the client-made answer id plus a rubric version). Model output is not deterministic, so idempotency means returning the stored first result, not re-running.         |
| Inject time and id generation.                                                                           | Already done                | The remaining gap is the learner's time zone.                                                                                                                                                                 |
